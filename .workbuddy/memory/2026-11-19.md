### 初始化（构建顺序，必须按此）
1. 根目录 `go mod download` / `go mod tidy`

## 修复 task dev 的 awk 报错 + 程序无法启动 + 清除无用代码

### 1) task dev 报 "awk: executable file not found in $PATH"（exit 127）
- 根因：`Taskfile.yml` 顶层 `vars.VERSION` 用 `sh: awk ...` 从 build/config.yml 读版本号；Task 会**急切求值所有 vars**，Windows 上没有 awk，导致连 `task dev`（根本不用 VERSION）也失败。
- 修复：把 `VERSION` 改成静态字符串 `"0.1.8"`（与 build/config.yml 的 info.version 同步，改动需手动更新）。

### 2) 程序 panic 无法启动（真正的启动阻断）
- 启动 `bin/ltools.exe` panic：`regexp: Compile(...) invalid or unsupported Perl syntax: (?!`。
- 根因：`plugins/col1688/parse.go` 里电话正则用了 Go RE2 不支持的前瞻 `(?![0-9])`，且该 regexp 在 `init()` 里 `MustCompile`，进程启动即崩。
- 修复：`phoneRe` 去掉前瞻，改为 `(?m)(\d{11}|\d{3,4}[- ]?\d{7,8})`（更长 11 位手机放前面优先匹配）。
- 排查技巧：Go 的正则引擎是 RE2，**不支持** `(?!)`/`(?<!)`/`(?=` 等 Perl 前瞻后顾，写正则时避免。

### 3) Windows "Access is denied"（Go 构建缓存）
- `task dev` 跑 `go build` 时报大量 `C:\Users\56874\AppData\Local\go-build\...\-a: Access is denied`。
- 根因：先前被 `timeout` 杀掉、但子进程未清理的 `wails3.exe`/`node.exe(vite)`/`esbuild.exe` 仍持有 go-build 缓存文件句柄。
- 修复：`taskkill /F /IM wails3.exe`、`esbuild.exe`、`node_repl.exe` 清残留；必要时 `go clean -cache`。跑 dev 后台任务被 kill 后务必清子进程。

## 1688 插件显示与"打开浏览器"崩溃修复

- **插件不显示**：新插件 `c1688` 的 metadata 未设 `State`，注册进 registry 后为 `""`，而 Home 只展示 `enabled` → 在 `plugin.go` 补 `State: plugins.PluginStateInstalled`；同时手动把 `%AppData%/Roaming/ltools/plugins.json` 重写为仅含 c1688（enabled），并清掉 22 条旧插件僵尸记录、shortcuts.json 旧快捷键、applauncher/bookmark/imagebed/kanban 数据目录。
- **`c1688:log` 事件类型报错**（"data of type col1688.LogEntry does not match registered map[string]any"）：main.go 注册事件类型写错，改为 `application.RegisterEvent[col1688.LogEntry]("c1688:log")`。
- **看不到浏览器窗口**：`launch()` 未设 `Headless(false)`、无窗口参数，独立 profile 的 Edge 窗口不可见 → 加 `Headless(false)` + `start-maximized` + `window-size/window-position`。
- **应用 FATAL 崩溃**（`[launcher] Failed to get the debug url`）：根因是 go-rod 的 `MustLaunch/MustConnect/MustPage/MustEmulate` **失败即 panic**，且用户连点「打开浏览器」后残留 Edge 占用 profile/端口 8023 再次触发 → 全部换成可失败版本（`Launch()/Connect()/stealth.Page()/Emulate()`），`launch()` 幂等复用已连接浏览器，失败时 `OpenLogin` 只记日志+返回错误，前端弹 `打开浏览器失败：…`，不再拖垮主程序。
- 注意：**不要 `taskkill /IM msedge.exe`**——会误杀用户日常在用的 Edge 窗口；go-rod 用独立 profile，残留进程靠 launcher 的 `remote-debugging-port` 冲突提示让用户手动关窗口。

## 1688 浏览器采集抗风控（易被识别为自动化）

1688 的 `_____tmd_____` 风控抓的特征与 `plugins/col1688/browser.go` 对应改进：
- **UA 与真实浏览器品牌矛盾**（原用 Edge 启动却 Emulate 成 `Chrome/120`）→ 改成**不覆盖 UA**（用真实 UA），只补 `AcceptLanguage=zh-CN` + `Emulation.setLocaleOverride(zh_CN)` + `Emulation.setTimezoneOverride(Asia/Shanghai)`。
- **频繁新开自动化实例**（每次采集都 Launch）→ 加 `debugURLFromPort(port)` **优先接管已在跑调试端口的浏览器**（真实登录态/指纹最难识别）；没有才用 `launcher.NewUserMode()`（替代 `New()`，真实浏览器引擎+指纹）拉起。
- **异常启动旗标** `disable-web-security`/`start-maximized`/`allow-running-insecure-content` → 去掉，只留 `no-first-run`/`no-default-browser-check`。
- **CDP 自动化痕迹**（`navigator.webdriver`、`cdc_*`、`plugins` 长度、`window.chrome`）→ `hardenPage()` 注入抹除脚本。
- **机械翻页**（固定 3s + JS `click()`）→ `humanScroll()` 滚动浏览 + `humanDelay()` 2~4.5s 随机 + 鼠标 `MoveTo→Click`（真实输入轨迹）替代 `nx.click()`。
- 相关 API（go-rod v0.116.2）：`launcher.NewUserMode()`、`stealth.Page()`、`proto.EmulationSetLocaleOverride/TimezoneOverride`、`page.Mouse.MoveTo(proto.Point)/Scroll/Click(proto.InputMouseButtonLeft,1)`、`evalJSON` 直接 unmarshal 到指针（不返回 JSON 字节）。
- 验证：`go build .`/`go vet ./plugins/col1688/` EXIT 0；启动无 panic。
- 局限：stealth 只 patch 默认页；每次 `NewPage` 需重新 `stealth.Page`+`hardenPage`。1688 页面/选择器改版仍需实测微调 `extractPage`/翻页选择器。
